SECCIÓN F: MÉTRICAS EXPLICADAS (Clasificación Binaria)
================================================================================

**Accuracy:**
- Fórmula: (TP + TN) / Total
- Interpretación: % correcto global
- ⚠️ Engañoso si desbalanceado (95% accuracy con 95% clases negativas)

**Precision (Valor Predictivo Positivo):**
- Fórmula: TP / (TP + FP)
- Interpretación: de los positivos predichos, ¿cuántos son reales?
- Importante si falso positivo cuesta mucho (ej: spam)

**Recall (Sensibilidad, True Positive Rate):**
- Fórmula: TP / (TP + FN)
- Interpretación: de los positivos reales, ¿cuántos detectamos?
- Importante si falso negativo cuesta mucho (ej: diagnóstico)

**Specificity (True Negative Rate):**
- Fórmula: TN / (TN + FP)
- Interpretación: de los negativos reales, ¿cuántos predijimos bien?

**F1-Score:**
- Fórmula: 2 × (Precision × Recall) / (Precision + Recall)
- Interpretación: media armónica de Precision y Recall
- Usa si balancear ambas métricas es importante

**AUC-ROC:**
- Rango: 0.5 a 1.0 (0.5 = azar, 1.0 = perfecto)
- Interpretación: probabilidad de clasificar un par positivo/negativo correctamente
- ✓ Inmune al desbalance de clases
- ✓ Mejor métrica para comparar modelos en clasificación

**ROC Curve:**
- X: False Positive Rate (1 - Specificity)
- Y: True Positive Rate (Recall)
- Área bajo curva = AUC-ROC

**Precision-Recall Curve:**
- X: Recall
- Y: Precision
- Especialmente importante si desbalanceado

================================================================================
SECCIÓN G: NOTAS FINALES
================================================================================

1. **Desbalance de clases:** Si una clase >> otra:
   - Usa stratified split
   - Usa class_weight='balanced' en modelo
   - Evita Accuracy; usa Precision, Recall, F1, AUC-ROC
   - Considera oversampling (SMOTE) si dataset muy pequeño

2. **Threshold:** Por defecto es 0.5, pero no siempre es óptimo
   - Threshold alto (ej: 0.7) → menor FP, mayor FN (más selectivo)
   - Threshold bajo (ej: 0.3) → mayor FP, menor FN (menos selectivo)
   - Elige según costo de negocio

3. **Costo de errores:** En medicina, FN es crítico; en spam, FP es crítico
   - Esto afecta qué métrica optimizar (Recall vs Precision)

4. **RandomizedSearchCV:** scoring='roc_auc' es más robusto que scoring='accuracy'

5. **Feature Importance:** XGBoost vs Logistic Regression
   - XGBoost es no-lineal, puede captar interacciones
   - Logistic Regression es interpretable (coeficientes = importancia)

6. **Siempre visualiza:** Curva ROC, matriz confusión, PR curve
   - Un modelo con AUC=0.85 pero matriz confusión rara = problema

7. **Probabilidades:** Siempre guarda predict_proba, no solo clases
   - Permite analizar confianza y ajustar threshold
